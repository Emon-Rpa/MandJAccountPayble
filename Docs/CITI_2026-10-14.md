# CITI behaviour and where it is configured (2026-10-14, untested in Studio)

Everything bank-specific lives in `Excel/Cash_Management_Entry.xlsx`:

| Sheet | Holds |
|---|---|
| `CITI` | Event map: Advice_Required, LC_Required, Account_Section, `Review` (NEEDS DECISION skips the event) |
| `CITI_Rules` | Rules (Section, Key, Value, Used_In, Notes): mail window, LC regex, advice labels and regexes, output columns, accounts, expense types |
| `CITI_Units` | Statement account number -> unit initials (CAL, CGL, GFL, CWPL), read by Bank_Statement (CITI branch) |
| `Bank_Config` | Which sheets belong to the bank |

## Flow per CITI statement row
1. `Bank_Statement.xaml` (CITI branch): reads the statement, unit from `CITI_Units`, writes DATA_PREPARATION.
2. `Advice_pdf.xaml`: classifies the row from the event map, searches the same-day mail, calls `CITI_advice_reader.xaml`.
3. Advice reader: LC (`Adv_LC_Regex`), principal / interest / excise from the block between `Adv_Block_Start` and `Adv_Block_End` using `Adv_*_Label` and the two amount regexes, bill currency and amount.
4. Routing (`Advice_pdf.xaml`): principal rows -> TT; if the LC country matches `Machinery_Country_Keywords` -> GRN, which becomes Machinery at the end. An EUR bill (`Eur_Bill_Currency`) also fills the EUR columns. Interest and Excise Duty are written on the row (headers renamed by `Rename_INT_AMOUNT`, `Rename_EXCISE_AMOUNT`).
5. Machinery interest split into Asset_Value / Interest_Value is NOT built: a later module supplies loan, asset and tenor dates in a second cycle.
